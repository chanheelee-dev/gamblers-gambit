# Gambling & Probability Primer

도박·확률 일반 개념의 간단한 primer. `gamblers-gambit` 디자인 결정 자체가 아니라, 디자인 문서(`docs/design/`)를 읽을 때 필요한 공통 배경 지식을 모은다.

디자인 문서에서 "EV", "하우스 엣지", "공정 배당" 같은 일반 용어를 만나면 여기를 참조.

---

## Expected Value (EV)

한 번의 베팅(또는 더 일반적으로 확률적 사건)의 **평균적 결과**. 가능한 결과 각각에 그 확률을 곱해 합산.

```
EV = Σ (확률_i × 결과값_i)
```

### 예시: 동전 던지기

앞면이면 +10, 뒷면이면 −10 을 얻는 게임:

```
EV = 0.5 × (+10) + 0.5 × (−10) = 0
```

이런 게임을 **공정(fair)** 하다고 부른다. 100 번 하면 평균 0, 단기적으로는 오르내리지만 장기적으로 0 에 수렴 (대수의 법칙, law of large numbers).

### "장기" 의 함정

EV > 0 이라도 **variance (분산)** 때문에 단기적으로는 크게 질 수 있다. 뱅크롤이 충분하지 않으면 장기 수렴 전에 파산할 수 있음 — TODO 섹션 `Variance 와 파산` 참조.

### 본 프로젝트에서

한 라운드의 EV 는 정답률 `p`, win payout, loss multiplier 로 결정:

```
EV_round = p × win_payout − (1 − p) × loss_mult
```

의도적으로 `EV_round < 0` (하우스 엣지 존재) 를 유지하되, 플레이어가 "안 하는 게 낫다" 라고 학습하지 않도록 `α`, `β` 상한을 제한 (설계 문서 §1.1).

## House Edge

도박 운영자(house) 관점의 장기 기대수익률. 플레이어 관점에서는 **매 베팅당 평균적으로 잃는 비율**.

```
house_edge = − EV_per_bet / bet_size
```

### 직관

공정한 동전에 2 배 배당이면 EV = 0 → 엣지 0%. 실제 카지노는 여기를 비틀어서, 같은 동전에 **1.95 배** 배당을 주면:

```
EV_per_1unit = 0.5 × (+0.95) + 0.5 × (−1.0) = −0.025
house_edge = 2.5%
```

1만 원 베팅하면 평균 250 원은 집이 가져감. 단판 승부가 아니라 **장기 누적**에서 드러남.

### 참고 수치 (실제 카지노)

- 블랙잭 (베이직 스트래터지): ~0.5%
- American 룰렛: ~5.3%
- 슬롯 머신: 5~15%
- 스포츠 베팅 vig: ~5%

### 본 프로젝트에서

`skill tax (α, β)` 가 엣지의 손잡이. 의도된 특성:

- `α = β = 0` → 엣지 0%, 공정.
- `α, β > 0` → 엣지 > 0%, 플레이어는 장기적으로 뱅크롤 감소.
- **V (난이도) 축에서 비균일** — `s(V) = V / 100` 이 0 에 가까운 (어려운) 구간은 엣지 작고, 1 에 가까운 (쉬운) 구간은 엣지 큼. "어려운 문제는 공정에 가깝게 보상" 이 설계 의도 (§1.1, §4).

## Fair Odds / Base Odds

EV = 0 을 만드는 이론적 배당.

### 도출

정답률이 `p`, 맞으면 `A` 배 순이익을 얻고, 틀리면 원금 1 단위 손실이라 하자.

```
EV = p × A − (1 − p) × 1
```

`EV = 0` 조건에서 `A = (1 − p) / p`. 이 값을 **base odds** 혹은 **fair odds** 라고 부른다.

### 예시

- `p = 0.5` → `base_odds = 1.0` (순이익 1 배, 즉 1 유닛 베팅하면 1 유닛 이득)
- `p = 0.8` → `base_odds = 0.25` (쉬운 문제 → 이겨도 25% 만 이득이 공정)
- `p = 0.2` → `base_odds = 4.0` (어려운 문제 → 이기면 4 배가 공정)

즉, **맞출 확률이 높을수록 fair odds 는 낮고** (쉬운 문제는 적게 줘야 공정), **맞출 확률이 낮을수록 높다** (어려운 문제는 크게 줘야 공정).

### "Decimal odds" 와의 차이

스포츠북·카지노가 표시하는 **decimal odds** 는 보통 원금 포함 총 배당(원금 + 이득)이다. 예컨대 decimal odds 2.0 = 순이익 배수 1.0. 본 프로젝트의 `base_odds` 는 **순이익 배수만** 을 가리킨다. 혼동 주의.

### 본 프로젝트에서

```
win_payout = base_odds × (1 − α × s(V))
```

공정 배당을 기준선으로 깔고, skill tax 로 축소해서 하우스 엣지를 만든다.
